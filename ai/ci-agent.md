# Autonomous improvement sessions

Use this workflow only when the user requests an improvement session. The root
[AGENTS.md](../AGENTS.md) and the user's scope govern the work; this document does
not authorize unrelated balance changes, commits, pushes or deployments.

Read [the developer index](../docs/README.md), relevant implementation, active
backlog and recent [improvement notes](state/continuous-improvement.md). Select a
concrete player/developer problem with evidence and a cohesive achievable change.
Treat old recommendations as candidates; do not repeat solved audits or promote
an agent proposal into approved game design.

Preserve the game's identity, established progression and visual feedback. Work
through existing scene ownership, effects, turn/occupancy, settings and persistence
paths. Prefer a focused fix over a new generalized framework. Do not add external
dependencies or refactor working systems solely for stylistic consistency.

Implement the working increment and run bounded checks from
[testing](../docs/testing.md). Visual claims require actual native inspection;
bot outcomes do not establish balance. Stop retrying unchanged failing commands
and report unrelated baseline failures while progressing on independent work.

Update affected authoritative docs and the relevant task/handoff when continuity
is needed. Keep improvement notes concise: completed change, evidence, limits and
high-value remaining work. Do not create a routine permanent audit or diary for
every command. End with concrete outcomes and actual validation, not promises or
unsupported performance/quality claims.
