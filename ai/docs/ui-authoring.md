# UI authoring

- `resources/themes/rift_ui.tres` is the project theme and the only theme referenced by first-party scenes. Edit shared fonts, colors, spacing, surfaces and state styles there. Legacy theme resources remain for compatibility; do not wire new scenes to them.
- Use named type variations: `CardFace` and its hover/modified states, `CardCostUnavailable`, `EnemyQueueEntry`, `ObjectiveQueueEntry`, `PriceUnavailable`, `CollapseDanger`, typography roles, and reusable inset/stack/row roles. Theme palettes also supply map icons, rarity colors and intent accents.
- Fixed UI structure belongs in `.tscn` scenes. Prefer containers for content, anchors for screen regions, and authored minimum sizes for intrinsic art/icon dimensions. Use `HFlowContainer` for collections that should wrap. A visual's minimum size must describe its drawn bounds, so parent containers can measure it correctly.
- Scripts bind data, update text/visibility, select theme variations, instantiate repeated scene instances, and handle interaction. Dynamic hand geometry, cursor aiming, world-to-screen coordinates, content-dependent scroll heights and state transitions legitimately need code. Expose motion tuning in the owning scene; do not assign fixed panel geometry or construct styles in `_ready()`.
- Use native button disabled/hover/pressed/focus states. Interactive card hit areas belong to the card container, not its decorative children. Preserve keyboard activation and visible focus.
- Keep styleboxes shared and immutable. Select another variation for a state change. Author shader parameters in material resources, with per-instance material state where animation changes it.
- Each component owns its children. Put status handlers in StatsUI, counters in CardPileButton, and confirmation actions in CardPopup. Do not inject children into another instance's private hierarchy or enable editable children to wire gameplay dependencies. The parent composition root binds player, board, camera and presentation components through their public properties or signals.
- Run composes a run HUD, map legend, pause menu and run tutorial. GameWorld composes a battle HUD and battle tutorial. EnemyHandler receives the typed enemy rail from that composition root; it does not search for whichever UI happens to be first in a global group.
- Fullscreen shader effects must multiply by incoming COLOR so CanvasItem modulation actually fades them. Keep fullscreen geometry stationary, animate dialog content about its own pivot, and advance on animation completion. Transient battle presentation must finish even if a tutorial pauses gameplay. Detach old views before attaching replacements.
- The scene/resource guard rejects local theme overrides, LabelSettings assignments, legacy scene themes and runtime Control/style construction. Tests use disposable Control fixtures and are excluded.
- `python tools/validate_project.py --godot <executable>` runs offline checks directly against the original project. Never create duplicate test projects. `--capture-ui` exercises native Forward+ rendering; disposable captures use system temp storage and are removed afterward. Export specific captures explicitly when visual review is needed; headless checks do not establish visual quality.
